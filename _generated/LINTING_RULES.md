### naming/marketplace-kebab-case

[↑ Table of contents](#table-of-contents)

**Applies to:** marketplace name - checked at the `identity` stage

**Requirement:** Is kebab-case.

**Severity:** `error`

**Why:** The name appears in the install command users type; mixed case and underscores are easy to mistype and inconsistent across forks.

**You will see:**

```text
src/.metadata-MARKETPLACE.toml: marketplace name 'Not_Kebab-marketplace' is not kebab-case (naming/marketplace-kebab-case)
```

### naming/marketplace-suffix

[↑ Table of contents](#table-of-contents)

**Applies to:** marketplace name - checked at the `identity` stage

**Requirement:** Ends in `-marketplace`.

**Severity:** `error`

**Why:** The brand prefix used throughout generated output is derived by stripping that suffix; without it there is no brand to derive.

**You will see:**

```text
src/.metadata-MARKETPLACE.toml: marketplace name 'example-store' must end in '-marketplace' (naming/marketplace-suffix)
```

### naming/marketplace-brand

[↑ Table of contents](#table-of-contents)

**Applies to:** marketplace name - checked at the `identity` stage

**Requirement:** The name with `-marketplace` removed is non-empty and kebab-case.

**Severity:** `error`

**Why:** That remainder becomes the brand prefix on every published plugin.

**You will see:**

```text
src/.metadata-MARKETPLACE.toml: marketplace name '-marketplace' leaves brand '', which is empty or not kebab-case (naming/marketplace-brand)
```

### naming/marketplace-not-reserved

[↑ Table of contents](#table-of-contents)

**Applies to:** marketplace name - checked at the `identity` stage

**Requirement:** Is not a reserved identity.

**Severity:** `error`

**Why:** Some names are rejected outright by the CLI and others collide with built-in scopes; either way the marketplace fails to register.

**You will see:**

```text
src/.metadata-MARKETPLACE.toml: marketplace name 'builtin' is reserved (naming/marketplace-not-reserved)
```

### naming/marketplace-length

[↑ Table of contents](#table-of-contents)

**Applies to:** marketplace name - checked at the `identity` stage

**Requirement:** Is 3 to 64 characters.

**Severity:** `error`

**Why:** Keeps the install command a user types readable and typo-resistant.

**You will see:**

```text
src/.metadata-MARKETPLACE.toml: marketplace name 'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-marketplace' is 72 characters, outside 3-64 (naming/marketplace-length)
```

### naming/folder-kebab-case

[↑ Table of contents](#table-of-contents)

**Applies to:** capability folder name - checked at the `capability` stage

**Requirement:** Is kebab-case.

**Severity:** `error`

**Why:** The folder name flows into the published plugin name and the install command; it has to survive being typed by hand.

### naming/folder-length

[↑ Table of contents](#table-of-contents)

**Applies to:** capability folder name - checked at the `capability` stage

**Requirement:** Is at most 32 characters.

**Severity:** `error`

**Why:** It is only one segment of a longer composed name; an overlong folder makes the full identifier unwieldy.

**You will see:**

```text
src/skills/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa: folder name is 40 characters, over the 32 limit (naming/folder-length)
```

### naming/plugin-id-unique

[↑ Table of contents](#table-of-contents)

**Applies to:** generated plugin identifier - checked at the `generated` stage

**Requirement:** Is unique across the marketplace.

**Severity:** `error`

**Why:** Two plugins sharing an identifier means one is unreachable after install, with no error to explain why.

**You will see:**

```text
_generated/claude-code/skill-beta/.claude-plugin/plugin.json: plugin identifier 'example-skill-alpha' is already used by 'skill-alpha' (naming/plugin-id-unique)
```

### naming/plugin-id-composed

[↑ Table of contents](#table-of-contents)

**Applies to:** generated plugin identifier - checked at the `generated` stage

**Requirement:** Is composed as `<brand>-<type>-<folder>`.

**Severity:** `error`

**Why:** The composed shape is what users see and type; a deviation silently changes the documented invocation.

**You will see:**

```text
_generated/claude-code/skill-alpha/.claude-plugin/plugin.json: plugin identifier 'wrong-prefix-alpha' should be 'example-skill-alpha' (naming/plugin-id-composed)
```

### hygiene/no-packaging-in-source

[↑ Table of contents](#table-of-contents)

**Applies to:** capability folder - checked at the `capability` stage

**Requirement:** Contains no generated-packaging directory (`.claude-plugin/`).

**Severity:** `error`

**Why:** Packaging is generated; a hand-written packaging file looks authoritative while being ignored, which has misled readers for months at a time.

**You will see:**

```text
src/skills/ok-skill/.claude-plugin: source folders must not contain .claude-plugin/ — plugin metadata belongs in .metadata-SKILL.toml and packaging is generated (hygiene/no-packaging-in-source)
```

### hygiene/no-self-referential-skills-path

[↑ Table of contents](#table-of-contents)

**Applies to:** generated plugin manifest `skills` path - checked at the `generated` stage

**Requirement:** Points at a subdirectory, never at the plugin root.

**Severity:** `error`

**Why:** A path resolving to the plugin root makes a consumer copy the plugin into itself; one such consumer crashes outright rather than warning, so the skill silently never installs.

**You will see:**

```text
_generated/claude-code/skill-alpha/.claude-plugin/plugin.json: skills path './' resolves to the plugin root — declare a subdirectory such as './skills/' instead (hygiene/no-self-referential-skills-path)
```

### content/description-required

[↑ Table of contents](#table-of-contents)

**Applies to:** any markdown file with frontmatter - checked at the `file` stage

**Requirement:** Declares a non-empty `description`.

**Severity:** `error`

**Why:** It is both the relevance hint the agent reads and the marketplace catalog line; an entry without one is unusable in a listing.

**You will see:**

```text
src/skills/ok-skill/SKILL.md: frontmatter is missing or has an empty 'description' (content/description-required)
```

### content/json-parses

[↑ Table of contents](#table-of-contents)

**Applies to:** any JSON file in a source folder - checked at the `file` stage

**Requirement:** Parses as valid JSON.

**Severity:** `error`

**Why:** A malformed config is skipped at load time with the reason visible only in debug output.

**You will see:**

```text
src/skills/ok-skill/config.json: invalid JSON (Expecting property name enclosed in double quotes: line 1 column 2 (char 1)) (content/json-parses)
```

### content/bundled-file-exists

[↑ Table of contents](#table-of-contents)

**Applies to:** bundled-file references in JSON - checked at the `file` stage

**Requirement:** Every `${CLAUDE_PLUGIN_ROOT}/<path>` reference resolves to a file that exists in the folder.

**Severity:** `error`

**Why:** Catches the 'config points at a script nobody committed' failure, which otherwise surfaces only when a user runs the capability.

**You will see:**

```text
src/skills/ok-skill/config.json: references ${CLAUDE_PLUGIN_ROOT}/missing.py but that file does not exist (content/bundled-file-exists)
```

### naming/avoids-builtin-name

[↑ Table of contents](#table-of-contents)

**Applies to:** skill name - checked at the `capability` stage

**Requirement:** Does not shadow a built-in command name.

**Severity:** `warning` - advisory, does not block publishing

**Why:** A shadowing name may resolve to the built-in instead of the skill, depending on what else is installed. Advisory, because the namespaced form always resolves correctly.

**You will see:**

```text
src/skills/ok-skill: skill name 'compact' shadows a built-in command (naming/avoids-builtin-name)
```

### hygiene/metadata-keys

[↑ Table of contents](#table-of-contents)

**Applies to:** `.metadata-SKILL.toml` - checked at the `capability` stage

**Requirement:** Parses as TOML and declares only `description` (a non-empty string).

**Severity:** `error`

**Why:** Only `description` is read by the generator; any other key is dead weight that a reader will assume does something.

**You will see:**

```text
src/skills/ok-skill/.metadata-SKILL.toml: keys ['name'] are not read by the generator (hygiene/metadata-keys)
```

### hygiene/folder-matches-name

[↑ Table of contents](#table-of-contents)

**Applies to:** skill folder in the multi layout - checked at the `capability` stage

**Requirement:** The folder name equals the frontmatter `name`, when one is set.

**Severity:** `error`

**Why:** Packaging is keyed by folder name while the agent surfaces the frontmatter name; if they disagree the same skill has two user-visible names.

**You will see:**

```text
src/skills/multi/skills/alpha/SKILL.md: frontmatter name 'renamed' does not match folder 'alpha' (hygiene/folder-matches-name)
```
